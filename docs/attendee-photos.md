# 참석자 사진

설정 → 참석자의 **참석자 사진 표시**를 켜면 이름 옆에 40px 사진이 나타납니다. 기본값은 OFF이며 계정별로 저장됩니다. 설정에서는 사진을 눌러 선택·교체·삭제하고, 오늘 주문에서는 사진을 눌러 확대합니다. 참석 여부와 음료·옵션·선호 메뉴 입력은 기존 위치와 폭을 유지합니다. OFF는 파일 삭제가 아니라 표시 중지이며, 사진 서명 URL 요청과 파일 다운로드를 하지 않습니다.

## 파일 처리

- 사용자 기기의 브라우저에서 긴 변을 최대 320px로 축소하고 JPEG로 다시 인코딩합니다. 작은 사진은 확대하지 않습니다. 투명 부분은 흰색 처리합니다.
- 먼저 약 50KiB 이하를 목표로 압축하며 최종 상한은 100KiB입니다. 원본은 서버에 올리지 않습니다. 20MiB 초과 입력, 8천만 화소 초과 이미지, 변환 실패는 안내 후 중단합니다.
- JPG·PNG·WebP를 지원합니다. HEIC/HEIF는 해당 브라우저가 해독할 수 있을 때만 처리하고, 지원하지 않으면 JPG·PNG·WebP 선택을 안내합니다. 모든 휴대폰의 HEIC 지원을 보장하지 않습니다.
- 사진 한 장만 보관하므로 참석자 100명이 모두 최대 크기를 써도 약 9.8MiB입니다. 교체·삭제 후 파일은 Storage API로 정리합니다. 중단된 업로드 등 1시간 이상 된 미참조 파일은 다음 연결 때 최대 100개 정리합니다. 연결이 없으면 자동 작업은 실행되지 않습니다.

## 계정 보호와 동시 수정

`007_attendee_photos.sql`은 계정별 표시 설정과 참석자 사진 경로만 DB에 저장합니다. 파일은 비공개 `attendee-photos` 버킷의 `계정 UUID/참석자 ID/임의 UUID.jpg` 경로에 저장합니다. 버킷은 JPEG만, 최대 102400바이트를 허용합니다. RLS는 승인된 본인 계정만 읽기·새 파일 업로드·미참조 파일 삭제를 허용합니다. 덮어쓰기는 차단하고 교체 시 새 경로를 발급합니다. 표시할 때만 1시간 유효한 서명 URL을 받아 메모리에 캐시합니다.

사진 변경은 기존 `account_state`의 행 잠금과 revision을 함께 사용합니다. 다른 기기가 먼저 저장하면 충돌로 중단하며 기존 주문이나 사진을 덮어쓰지 않습니다. 요청 계정과 실제 로그인 계정도 비교합니다. 계정 전환 중 늦게 도착한 응답은 버립니다. 사진 RPC 응답이 불명확한 네트워크 실패에서는 이미 저장됐을 수 있는 새 파일을 즉시 삭제하지 않습니다.

오늘 주문 초기화는 사진·표시 설정을 보존합니다. 관리자 전체 초기화는 현재 계정의 사진 연결과 표시 설정도 초기화합니다. 실제 파일은 Storage API 정리 대상이 됩니다. 사진은 주문 완료 스냅샷에 포함되지 않으며 완료 주문의 음료·금액을 바꾸지 않습니다.

기존 `save_state` 본체는 `save_catalog_state`로 이름을 바꾸고 외부 호출 권한을 회수합니다. 새 `save_state`가 기존 검증을 호출한 다음 전체 초기화 때 사진 표시 설정을 같은 트랜잭션에서 지웁니다. 이후 주문 SQL을 수정할 때 이 래퍼 구조를 유지해야 합니다.

## 백업과 적용

JSON 백업에는 `photoMetadata`(표시 설정·경로)만 추가합니다. 사진 바이너리와 서명 URL은 포함하지 않습니다. 기존 JSON 가져오기는 사진 파일을 복원하지 않습니다. 별도 사진 백업/일괄 복원 기능은 이번 범위에 포함하지 않습니다.

2026-10-29 사용자 배포 요청에 따라 007을 운영에 적용했습니다. 적용 직전 orderpick_backup_007에 기존 8개 업무 테이블과 save_state 함수를 비공개·RLS 백업하고, 적용 후 자료 건수를 비교했습니다. 비공개 JPEG 버킷(102400바이트), 익명 RPC 실행 거부, 내부 catalog RPC 직접 호출 거부를 운영 SQL로 확인했습니다. 실제 Supabase Storage/Auth/PostgREST에서 두 계정의 업로드·조회·삭제 검증은 별도입니다. 007이 없는 서버에서는 사진 설정을 비활성화하고 기존 주문 기능을 유지합니다.

로컬 미리보기는 `node tests/photo-preview.cjs` → http://127.0.0.1:4174 입니다. 운영 환경변수를 읽지 않으며 가짜 계정과 검증 자료를 메모리에만 둡니다. 종료하면 사라지고 공개 빌드에는 포함되지 않습니다. 이 서버는 개발용이며 배포하지 않습니다.

검증 명령: `npm test`, `npm run test:db`. 후자는 Storage 메타데이터와 RLS를 로컬 PostgreSQL에서 검증하며 실제 Supabase 파일 업로드 API 검증을 대신하지 않습니다.

참고: [비공개 버킷과 제한](https://supabase.com/docs/guides/storage/buckets/fundamentals), [Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control).
