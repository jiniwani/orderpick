# 계정별 데이터 분리 및 무료 운영 설계

상태: 로컬 구현 및 PostgreSQL 검증 완료. 자동 승인 검토 차단 후 사용자가 백업·계정 분리·배포를 명시적으로 승인했습니다. 운영 DB 005·006 적용, 원본 건수 보존 및 A/B 롤백 검사 통과. 프런트엔드 검증 결과는 TESTING.md 참조.

## 계정별 동작

- 로그인 필수, 같은 계정은 PC/휴대폰에서 같은 데이터를 사용합니다.
- 계정 A와 B의 카페·메뉴·참석자·선호도·주문·기록은 독립적입니다.
- 기존 공용 데이터는 기존 승인 관리자 계정의 소유 데이터로 이전하고 새 계정은 빈 상태로 시작합니다.
- 회원은 관리자가 Supabase Auth에서 발급합니다. 공개 회원가입은 비활성 상태를 유지합니다.
- 일반 사용자 로그인과 시스템 관리자 권한을 분리합니다. 관리자 여부가 다른 계정의 데이터 열람 권한을 자동으로 부여하지 않습니다.

## DB 변경 원칙

1. 업무 테이블에 account_id를 추가합니다. 소유자는 요청 JSON이 아니라 auth.uid()로 정합니다.
2. 카페 이름·참석자 이름·날짜 유일 제약은 계정 범위로 변경합니다.
3. 외래키는 다른 계정의 카페·메뉴·참석자를 참조할 수 없도록 계정 범위를 함께 검증합니다.
4. 모든 RLS 정책과 SECURITY DEFINER RPC에 계정 조건을 적용합니다. 다른 계정 ID를 조작해 보내도 삽입/수정/삭제할 수 없어야 합니다.
5. 저장 버전과 잠금은 계정별로 분리해 다른 사용자의 저장이 충돌을 만들지 않도록 합니다.
6. 비로그인 업무 테이블 조회/저장 권한을 회수합니다. 공개 publishable key만 프런트엔드에서 사용합니다.
7. 전체 초기화와 삭제는 현재 계정 범위에만 적용합니다. 기존 완료 잠금·날짜 유일성·동시 수정 보호·안전한 DELETE 조건을 유지합니다.
8. 기존 자료를 보존하고, 전환 전 백업과 전환 후 계정별 건수 비교를 수행합니다.

## 사용량 절약

- 5초 전체 데이터 폴링을 계정별 경량 버전 확인으로 교체합니다.
- 화면이 숨겨져 있을 때 폴링을 멈추고, 앱 복귀·수동 새로고침 때 변경 여부를 확인합니다.
- 버전이 바뀐 경우에만 현재 주문과 공용 설정을 다시 받습니다. 기록은 필요한 개수만 조회합니다.
- 완료 스냅샷은 기존 기록 재현 동작을 유지하기 위해 당시 설정을 보존합니다. 계정 백업은 전체 주문 기록을 포함합니다. 저장량은 누적되므로 프로젝트 DB 용량을 확인해야 합니다.
- 초기 범위는 텍스트 데이터만 저장하고 첨부 이미지 업로드는 제공하지 않습니다.
- 보관 기록은 증가하므로 JSON 내보내기와 사용자가 선택하는 보관·정리 정책이 필요합니다. 무기한 기록 누적과 영구 무제한 무료를 동시에 보장하지 않습니다.
- OTP/SMS 대신 이메일·비밀번호 로그인 중심으로 구성합니다. 직접 가입·메일 인증/비밀번호 재설정은 별도 SMTP 설정이 필요합니다.

## 무료 요금제 검토 (2026-10-29 공식 문서 확인)

- Supabase Free: 전체 프로젝트 DB 500MB, 월 전송 5GB, 월 활성 사용자 50,000명. 1주 비활성 시 프로젝트 일시중지 가능.
- Vercel Hobby: 개인·비상업용 제한. 여러 사업장의 업무용 운영은 무료 사용량 외에 이용 조건도 확인해야 합니다.
- Cloudflare Pages: 정적 요청은 무료·무제한으로 안내하며 서버 Functions는 별도 Workers 한도 적용. 현재 앱은 정적 파일과 Supabase API로 구성할 수 있습니다.
- Supabase 기본 메일 발송은 운영용이 아니며 조직 구성원 주소와 시간당 2건으로 제한됩니다. 비밀번호 로그인 자체와 이메일 발송량은 구분합니다.

## 필수 검증

- A가 등록/수정한 카페·메뉴·참석자·선호도·주문은 B에게 조회되지 않음.
- 동일 이름/동일 날짜를 서로 다른 계정에서 독립적으로 사용할 수 있음.
- 요청 body와 객체 ID를 조작해 다른 계정 자료에 접근/수정/삭제할 수 없음.
- 같은 계정의 두 브라우저 간 저장 복원·버전 충돌·완료 잠금 동작.
- 로그아웃/계정 전환 시 이전 계정 화면 데이터 즉시 비움.
- 현재 운영 데이터의 계정 이관 전후 카페·메뉴·참석자·주문 건수 동일.
- 다른 계정의 작업이 내 계정의 저장 버전을 변경하지 않음.
- 관리자 계정 발급 방식으로 전환. Cloudflare Pages용 정적 보안 헤더와 배포 지침 제공. 호스팅 이전은 계정 연결 및 새 도메인 확인 후 수행.

## 화면 구성

상단은 오늘 주문·주문서·설정 3개 탭입니다. 설정 안에 참석자·선호 메뉴, 카페·메뉴, 데이터 관리가 있습니다. 로그인은 상단 버튼으로 여는 모달입니다. 씨젠의 CI 빨강을 참고한 앱용 빨강 계열을 사용하며 공식 로고를 사용하지 않습니다.
